# Verification limits and follow-ups

- **Generative/Open UI deferred:** Pages and streamed responses use ordinary rich text/Markdown. Widget insertion and automatic card hydration are removed. Legacy content remains readable and copyable without a bulk vault rewrite; unknown or malformed data stays literal.

- **Workflow overhaul follow-ups:** Settings and foreground generation gates are the first phase described in [workflow configuration](features/workflow-settings.md). The synthesis-template library still lacks a user create/edit/duplicate/delete manager. Resume now has its own read-only factual path, explicit model-selected excerpts and shared cache. The old deterministic core builder remains for legacy APIs/tests; the desktop Resume commands use the new path. Automatic/background summaries remain off. Existing explicitly created trackers retain their schedules and pause when their workflow is disabled.
- **Refine and Derive generation fallbacks eliminated and project context secured (Batch 1 + follow-up):** `refine_artifact` and `derive_artifact` validate model responses and return honest errors on provider failures, timeouts, malformed JSON, or empty content without fabricating "Critique Addressed" notes or synthetic derived pages. The saved source, Markdown mirror, revisions, change sets, artifact count, lineage and project membership remain completely unchanged on failure. Derive now takes explicit destination project context from `FocusView`: deriving within an active project context attaches exclusively to that project; single-project sources inherit their unambiguous parent project; shared sources across multiple projects or loose sources without context remain standalone without arbitrary `LIMIT 1` selection. Template skeleton outbound prompt injection and disabled-template omission are verified with prompt capture assertions. Guided-research and template library management follow-ups remain tracked separately.
- **Request lifecycle, timeouts, and cancellation reliability (Batch 2 + follow-up):** Connection timeouts (10s), model generation budgets (180s standard, 45s quick_task), streaming inactivity limits (30s inactivity, 60s initial TTFT), overall workflow deadlines (185s standard, 60s quick_task), and cooperative cancellation are decoupled in `RequestPolicy`. Reqwest network errors are classified using `err.is_timeout()` and `err.is_connect()` into distinct `RequestErrorKind` variants rather than fragile substring checks, ensuring connection establishment failures (10s) fail fast without waiting for the 180s generation budget, and slow but progressing local generation (e.g. CPU `llama3.2:latest` generating ~3.73 tokens/s) has up to 180s to complete without premature caller termination. Cooperative cancellation via `CancellationToken` and desktop `RequestRegistry` coordinates an explicit atomic state machine (`Running -> Cancelled` vs `Running -> Committing -> Completed`). Inside the database writer lock, `apply_refinement_with_cancellation` and `create_derived_artifact_with_cancellation` check cancellation before opening transactions or modifying disk mirrors; cancellation arriving during inference, clock timestamp generation, or writer lock contention reliably aborts with zero mutations. If the commit boundary has already been entered, cancellation attempts truthfully return `CancelOutcome::AlreadyCommitting` or `Completed` (`cancel()` returns `false`), preventing misleading cancellation status. Successful refinement in `apply_refinement_with_cancellation` computes content materiality and records an `artifact_updated` durable session event in the transaction linking the ChangeSet ID and associated projects, updating `projects.last_substantive_at` when substantive. In the desktop UI, `RefineArtifactModal` automatically cancels active in-flight requests and cleans up request identity when the note changes or the modal unmounts; `FocusView` verifies `targetArtifactId === currentId` before applying updates, preventing late responses from overwriting switched documents. If cancellation is rejected by the backend because persistence has begun (`cancelRequest` returns `false`), `RefineArtifactModal` captures a draft snapshot: if the draft is unmodified upon resolution, the committed result reconciles into the editor; if the user wrote a newer draft to body or title after closing the modal, the newer draft is strictly preserved, no model result is fed into autosave or `saveArtifact`, and a non-destructive conflict banner (`banner-refinement-conflict`) offers explicit review/reconciliation. In the conflict banner, "Keep My Draft" and "Apply Refinement" explicitly persist the chosen version to disk/database via a shared conflict persistence handler, canceling pending autosave timers and coordinating with active saves; update last-saved tracking and dismiss the conflict only after confirmed persistence; recheck ownership across every asynchronous boundary (including `getArtifactContext` error and success paths, notifications, and callbacks) preventing stale context refreshes or navigation from altering active document identities or save targets; on save failure, both conflict versions and recoverable drafts are retained with honest retryable errors; and same-artifact reloads under new load generations reject stale completions. On provider failures, `RefineArtifactModal` preserves the critique draft and displays actionable failure messages while immediately re-enabling the Run button for retry without closing the modal; late rejections from cancelled requests do not cancel active retry indicators. Automated native integration testing covers 32 lifecycle tests in `request_lifecycle_test.rs` (including session event durability on refine, zero events on cancelled refine, pre-write clock cancellation intercepts for refine and derive, writer lock contention cancellation, commit-wins ordering, slow success >60s, overall deadline, deterministic connect timeout via hanging handshake, provider vs caller deadline precedence, boundary cancellation, immediate retry, production command cancellation, multi-document concurrent isolation, typed HTTP status error retention, body-read timeout classification, quick naming budget enforcement, and streaming header/body/heartbeat bounds). UI component tests in `chained_synthesis.test.tsx` cover 25 tests including retry without closing modal, document-switch isolation, stale rejection isolation, cancellation rejection reconciliation on unmodified draft, newer user draft preservation with save protection, Keep My Draft durability across autosave and remount, unsaved draft Keep persistence, retryable Keep save error handling, Apply Refinement explicit persistence before and after autosave with reopen durability, retryable Apply save errors, navigation isolation during pending Apply/Keep saves, and stale refresh error/success isolation across navigation and load generations. Native GUI cancellation/retry and live multi-minute local model performance remain separate manual/live acceptance layers.

This file tracks unresolved work, not a whole-product pass/fail certificate. Update an item only with evidence from the execution layer it names. Permanent requirements live in [policies](policies/README.md).

- **Full native visual and lifecycle verification remains open.** Engine-reopen integration, mocked components, and browser spot checks do not establish a current page-by-page Tauri GUI pass, process restart, all responsive/theme/error states, or all eight connected journeys.
- **Live provider/web and cross-platform/assistive-tech execution remain unverified where unavailable.** Do not infer success from deterministic fake providers, test names, token tables, or another platform's browser.
- **External AI setup:** External-provider setup guides connection to separately installed apps. Resume separately manages an optional pinned local model/runtime download, without registering it as a provider. Task recommendation badges are hidden; their heuristic code is retained for future evaluation work. Information panels explain context capacity without rating model quality. Background model evaluations are not implemented. Existing catalog context values may be estimates; new missing context values remain unknown. Loopback HTTP fixtures and browser previews do not establish inference against installed Ollama or LM Studio, hardware suitability, or a native GUI pass.
- **Search keyboard/accessibility needs a complete pass.** Current source handles arrows/Enter on the input and restores an opener on dismissal, but Tab containment and activation of a directly focused result option are not established. Test stale async query/close results as well as happy-path input traversal.
- **Toolchain/performance checks must be reported honestly.** Clippy/rustfmt may require installed components. A frozen router test has a 50ms aggregate timing assertion that has been sensitive to concurrent build load; preserve failures/retests. The production bundle also has a size advisory; a successful build does not establish a startup performance measurement.

- **Document conversation scope:** discussion uses saved document context and the most recent 20 turns, without fresh web retrieval or tool execution. Browser rendering uses synthetic fixtures; native GUI and live-provider conversation execution remain unverified. Existing saved documents initialize a neutral conversation on demand.

The temporary audit reports and screenshots were removed at the owner's request. Their prior completion claims are not carried forward. Approved visual targets, reproducible tests, and product/design contracts remain.

- **Local Resume preview quality and platform scope:** SmolLM2-360M was selected for an optional download after a small CPU comparison with Qwen3-0.6B; neither passed every content check. Generated output is restricted to source-verbatim excerpts, verified before display, with current saved facts retained. This does not establish completeness, multilingual quality, semantic contradiction detection or general summarization accuracy. Linux x86_64 download/extraction/inference/removal has a real-model smoke test; the pinned macOS, Windows and Linux ARM runtime artifacts have not been executed here. Unsupported CPUs/system libraries or missing system `tar` fall back to workspace models or factual Resume. Background model work remains unimplemented.

- **Title suggestion quality:** Naming uses a separate composing prompt and explicit review/acceptance. In the small CPU naming comparison, SmolLM2-360M and Qwen3-0.6B each passed only three of seven automated content cases, and each returned valid title format on five. Keyword checks are incomplete: manual inspection found misleading wording even in a passing Qwen proposal case and a source-instruction failure in Smol. Neither justifies automatic renaming. The optional pack remains a preview; users can choose a connected model. Multilingual naming is unverified.
- **Document tabs execution scope:** Component tests and synthetic full-App browser checks exercise the new tab state and save guards. Native window-close/relaunch and platform shortcut interception are distinct and require native GUI execution. Tab metadata restores per vault; conversation drafts are retained within the browser/WebView session. Abrupt process termination can interrupt existing asynchronous autosave; tab restoration does not establish crash-proof recovery of unsaved edits. Split panes and multiple windows are not implemented.

- **Internal reference URLs:** Legacy inline citation code and canonical internal links are rendered inside the editor and reference preview, with exact URL/UUID lookup in workspace and connection search. This is in-app handling; OS-level registration/opening of the `sthira://` scheme from other applications remains unverified. Citation labels retain their saved wording; opening/searching resolves the current target title by identity. Missing/deleted sources remain unavailable, and inline citations do not silently create manual graph relationships.

- **Search and model checks are separate:** the Ollama `/v1/api/generate` routing mismatch is corrected with shared native API-base normalization across discovery, JSON, streaming and embeddings. Isolated HTTP tests cover successful search with both successful and failed model synthesis. An explicit live smoke against an existing local Ollama proxy/cloud model completed JSON generation and Research after normalization; DuckDuckGo returned zero results in that live run, so the output was labeled a local fallback. This does not establish live web-grounded retrieval for every query or a native GUI pass.

## Native page blocks and media

- Direct model-authored JSON fences inside an outer JSON Markdown string failed live validation with the configured Gemma model. The implemented JSON-workflow path now uses typed `page_blocks` beside the prose and application-owned serialization; a live three-block generation/save/mirror/reopen check passed. This is not a guarantee of valid output from every model.
- Native plan/comparison/choice blocks are a bounded first version, not arbitrary generated mini apps or executable OpenUI/HTML. Ordinary Markdown and malformed/unsupported block data remain available. Model support depends on valid output, not a model-name capability guess.
- Block choices/tasks are stored in page Markdown. They do not record workspace decisions or execute actions. Refinement and conversation proposals can still change model-generated content; review those changes before applying.
- Markdown image URLs and hyperlinks have editor/persistence coverage. Binary image clipboard paste, local attachment import/management and offline image caching are not implemented. Native OS-browser launch and native GUI block interaction remain separate, unverified checks.
