# Product contract

## Purpose and tone

Sthira is an AI-native, local-first workspace for thinking, research, planning, and durable knowledge. Its promise is: **Help me remember where I was, without making me revisit everything I did.**

The experience is calm, capable, trustworthy, exploratory, steady, and user-owned. Capture is lightweight; complexity appears when useful. Orientation is concise, with detail available on demand. No guilt, artificial urgency, streaks, fabricated progress, or repeated dismissed suggestions.

## Knowledge ownership and trust

- Artifacts retain their identity, authorship, content, revision history, and source attribution across reuse, movement, conversion, refinement, and derivation.
- User-recorded claims require actual user authorship and verified quote evidence. Hedges and questions are not recorded decisions. External evidence stays source-backed; saved/generated AI prose stays AI-authored/inferred until an explicit supported adoption action changes the relevant knowledge state.
- Every substantive brief/history claim must lead to inspectable evidence. Missing evidence and uncertainty are visible; plausible prose is not proof.
- AI-proposed structural changes remain inspectable, accept/dismiss controlled, and reversible where promised. Inference does not silently attach, move, link, or change project purpose. Accepted changes use the established change-set mechanism; dismissal persists.
- A transient answer does not become permanent workspace clutter until explicitly saved. Capture preserves user words, Research investigates, Plan produces steps, and Draft produces an AI deliverable. The internal `act` protocol remains compatible with the visible Draft label. Resume belongs to existing work; ambiguous-input handling retains its contract.

## Navigation and working context

- Opening a project from navigation opens its **overview**, never its first note or an unsolicited generated resume brief. Explicit Resume remains a separate intention.
- The overview shows saved purpose/status/dates, factual counts, active members, saved project canvases, and directly referenced/backlinked entities. Deduplicate by identity and retain all relationship labels. Do not flatten another project's contents into the current project.
- Search names/types/loaded summaries according to the actual search contract; combine type/relationship filters, stable sort, list/grid, and clamped pagination. Do not advertise full-text search if only summaries are searched.
- Selecting an entity opens that exact entity centrally. Project back restores the originating overview's search, filters, sort, layout, and page. An external/shared artifact keeps its correct editing context.
- A note is one formatted editable surface backed by Markdown. Do not restore a binary Edit/Preview workflow. Read-only reference previews remain read-only.
- Breadcrumbs are actionable: standalone pages show Pages, which opens All Files → Pages with Standalone scope. Project members show the actual saved project name and open its overview, including when opened through an identity-only entry point. Shared notes retain the explicitly selected project context. Do not derive project names from generated briefs. Clicking the current note name focuses its editable title. Save dirty text before leaving and retain the editor if saving fails.
- The note header exposes History, Connections, and truthful save state. Theme is in sidebar/Settings; Spatial canvas is in sidebar; evidence is in Page actions → Sources & insights.
- Preserve the original draft, selection/scroll where supported, and content identity while reading nested references. Back/trail/Escape retraces context predictably; opening a reference centrally saves the original safely first.
- Global search, sidebar, directories, graph, and workflow outputs resolve stable identities. Same-title entities must not be mixed.

- Document tabs keep one active rich editor. Ordinary note navigation reuses the active tab; Ctrl/Cmd-click or Open another document opens a separate context, deduplicated by artifact identity. Tabs remember the selected project, originating project, scroll position and document conversation draft. Save the active page before switching, closing or leaving; a failed save blocks navigation and preserves the draft. Closing a tab never deletes a document. Restore tab identities/context per vault on restart; explicit launch routes take precedence. Split panes are outside this implementation.

## Relationships and reuse

Keep these concepts distinct in storage, wording, and UI:

| Concept | Required semantics |
|---|---|
| Project membership | Many-to-many attachment of one artifact; Add existing does not duplicate its content/history. |
| Manual reference | Explicit directional connection with outgoing references and backlinks. Unlink preserves both endpoints and content; Undo restores the relationship once. |
| Derivation | Automatic source/child lineage from the user's Derive action. Save the newest draft first; preserve provenance and associations. Lineage is not a removable manual reference. |
| AI proposal | Suggested organization pending an explicit decision. It is not already an accepted relationship. |
| Spatial placement | Canvas position/layout only. Proximity creates neither semantic edges nor membership/evidence. |

Saved internal citations accept both `sthira://artifact/<id>` / `sthira://project/<id>` and the existing `#/sthira/...` links. Render old title-plus-code-URL references as named, keyboard-accessible links, including in read-only previews; do not rewrite a document merely by opening it. Fenced code remains literal. In-app search resolves a copied internal URL or exact UUID to the current saved entity, including after renaming, and excludes deleted targets. Opening a citation previews its exact identity and uses the existing guarded full-page navigation. Rendering/searching a citation does not create a manual connection or project membership.

Manual reference targets currently include projects and artifact-backed pages, typed objects, sources, and snippets. Canvases can be project contents but are not manual reference targets unless the owner explicitly extends that contract. Arbitrary text mentions and pasted external links do not silently create connection cards. Explicit Insert in page uses stable target identity and preserves surrounding content.

## Pages and rich text

- Pages is the shared document container and the navigation label (replacing Notes & Pages). A type describes a page's purpose/properties; it does not create a second editor or duplicate document. Keep existing artifact types, identities and saved titles compatible.
- Pages use ordinary rich text backed by Markdown: headings, paragraphs, lists, task lists, tables, links, images and code. Generative/Open UI cards, automatic Markdown-to-widget hydration, and widget insertion controls are deferred. Models must return readable document content rather than JSON UI definitions.
- Previously saved plan/comparison/choice fences remain readable and copyable as ordinary document text. Opening a page does not rewrite its saved source; a subsequent explicit edit saves the readable Markdown representation through normal save/history protections. Retain saved completion/selection information as text and preserve unsupported or malformed content literally. No bulk vault migration is performed.
- Markdown image URLs and external hyperlinks are supported by the document editor and read-only renderer. An image URL is not an imported local attachment or guaranteed offline asset; native attachment upload/paste and image caching need a separate storage workflow.

## Editing, lifecycle, and persistence

- Autosave, manual save, blur/navigation, and asynchronous generation must keep writes bound to the original artifact/project. Never overwrite a newly opened document with an older save result. A failed save retains a recoverable draft and cannot display success.
- Derive aborts on failed prerequisite save. Refine snapshots the prior state and provides the documented restore path. Late results must not leak into another run/document.
- Typing a slash at a block boundary or choosing Insert Block exposes formatting, epistemic, typed-object and AI actions. Keep the command menu within the viewport, preserve the editor selection when choosing an action, and support filtering, arrow keys, Enter, Escape, and IME input.
- Markdown round-trip preserves supported tables, tasks, code/language, links, raw directives, and embedded objects. Unsupported blocks must not disappear during surrounding edits.
- Object conversion preserves artifact identity/body; templates instantiate independent content. Shared properties and body remain consistent across contexts.
- Move/attach/detach is transactional. Deleting a project defaults to preserving its notes; explicit cascade respects shared artifacts. Dialog copy must describe actual consequences. Do not invent recovery for irreversible operations.
- SQLite, Markdown files, indexes, fingerprints, references, and UI state must reconcile correctly. Migration/reconciliation tests use copies or disposable vaults.
- Memory mirrors remain outside watched artifacts with their do-not-ingest marker, preventing recursive ingestion of AI summaries.

## Title suggestions

- Suggest a title is explicit and read-only until the user chooses Use title. Manual titles never change as a side effect of model generation, opening a document or loading a tab. Naming uses the configured Resume model by default, with a per-request connected-model/local-pack override. Requesting naming does not enable Resume summaries or modify its model choice. A factual-only Resume selection requires the user to choose a naming model.
- Show the selected model/connection before the request and retain producing model/provider attribution with suggestions. Read only a bounded saved excerpt; failed prerequisite saves block inference. Source text is untrusted. Suggestions compose new wording and need review; Resume's extractive validator is not a proof of title quality. Small-model quality limitations remain visible. No automatic/background rename is implemented.
- Apply checks the exact saved content hash and prior title atomically, preserves identity/authorship and body apart from a matching leading title heading, records a revision/event, and keeps the Markdown mirror consistent. Reject changed sources; a failed mirror write retains the prior saved title. Do not apply late suggestions to another document or overwrite a title edited after generation.

## Document conversation

- Every saved document, including files created before chat existed, offers a collapsible conversation tied to artifact identity. Missing conversation history is a normal empty state. Legacy documents start with an empty conversation and a neutral Document label; do not invent earlier messages or infer a workflow from the title. Store the original goal, messages, errors, and reviewed edit proposals in the vault database, separately from document content and evidence. Remember the panel preference across sessions.
- Discussion reads the saved current draft and recent conversation. Replies do not edit the page. Explicitly requesting an edit creates a full-document proposal with its original content basis; users inspect the current and suggested documents in a wide, read-only rich-text comparison before Apply or Dismiss.
- Apply rejects stale or already-reviewed proposals, records an AI revision and reversible ChangeSet, and keeps the document mirror in sync. Failed saves block model dispatch; failed generation keeps the attempted message and the draft. Late responses remain bound to their original document.
- The chat model selector remembers a catalog model ID per document, starting with the document’s generation model when recorded. Switching keeps messages, pending suggestions, and the unsent draft; it does not change the global default or another document. Each new turn snapshots the resolved model and provider names before inference. Preserve those labels after switching, renaming, removal, and reopening; older turns without attribution say Model not recorded. Reject unavailable/disabled selections without silently substituting a model.
- The conversation uses the configured model and document context. It does not imply new web searches or autonomous actions. The same entry point is available when a saved document originated from Capture or Act.

## Memory, research, scheduling, and settings

- Workflows are opt-in in Settings. Capture, editing, saved documents and conversation history stay available without AI setup. Research, Plan, Draft and document-chat generation require both an enabled workflow and an available configured model. Disabled workflows show a setup action and reject native generation before dispatch. Existing active trackers pause while their workflow is disabled without deleting their schedule or outputs.
- Model selection resolves task/document choice, then workflow default, then the workspace default. Preserve document conversation selections and attribution. Unavailable explicit models must not silently fall back. Research/Plan template pickers require their workflow and template option; disabled templates must not reach new Research/Plan runs. Template management remains planned. Resume uses a separate, explicit request with its configured model or a labeled factual fallback; it never silently substitutes another AI model for an unavailable explicit choice.
- Settings use one category navigation. Workflow preferences save immediately with failure feedback; connection edits retain explicit Save controls. Advanced capability overrides are collapsed. Demo seeding is confined to development tools and destructive vault actions live in a collapsed section. Keep provider setup distinct from user workflow preferences.
- AI setup starts with an empty provider/model catalog, including browser previews. Never seed an assumed Ollama installation or downloaded model. Offer guided external-app setup for Ollama and LM Studio, custom connections with an explicit API format, cloud providers, and Set up later. External-app setup does not install those apps or their models. Resume separately offers an explicit optional download of its pinned app-managed local model/runtime pack; it never adds an assumed provider connection. Preserve existing connections on upgrades. Distinguish untested, checking, reached-with-no-models, discovered-models, and failed checks; discovery does not certify generation. Connection checks are read-only and ignore responses for superseded drafts. Saving a connection and its chosen model is atomic; adding a connection preserves an existing workspace default.
- Model lists prioritize names, connection location, the default choice, and an information button; do not show task recommendation badges. The information panel provides technical metadata (including context window), cautious guidance about how much source material may fit, and model controls. Context capacity is not a measure of answer quality or task suitability. Retain the task-guidance code for future evaluation work, but do not run background evaluations or present unmeasured task ratings. Unknown or specialist models must not receive unsupported quality claims. Missing context metadata is unknown, not an invented limit; catalog/estimated context is distinct from the effective runtime setting. A local endpoint is not proof of local processing, especially for cloud-backed Ollama models.

- Resume is opened explicitly from project overviews or project documents. Reading it and expanding a cached review never dispatch a model or create proposals. Factual working state remains available with no model and with model summaries disabled. Its source packet is bounded to selected member documents and verified current decision/question quotes, excludes deleted/detached documents, and carries exact artifact identities. A requested model selects source-verbatim excerpts; changed wording, unknown citations, or unverified quotes are rejected. Model-selected excerpts remain AI-attributed and keep the factual working state separately available.
- Resume settings default to the workspace model, offer an explicit override, local pack, or factual-only mode, and configure source details/document limits. Model generation remains opt-in and on demand; no background/cloud jobs run automatically. An optional downloaded local pack may be used when no workspace default is configured, if enabled. Unavailable explicit models or failed generation retain cached valid results or current facts with truthful feedback. One project cache serves both review levels and fingerprints source revisions, settings, generator, and provider/model identity; late results must not overwrite changed sources or settings. The local runtime runs with bounded CPU/context and exits after each request. Its preview quality is limited and does not establish general model rankings.
- Level 1 orientation is capped at 75 visible words; Level 2 adds grounded detail. Follow deterministic cold-return/draft/conflict hints. Opening/typo/whitespace activity must not fabricate substantive progress; small meaning changes such as negation remain substantive.
- Cache correctness follows the documented basis fingerprint. Performance targets require measured paths and environments; they are not blanket native UI latency guarantees.
- Research/Plan stream in the center workspace. Carry the selected catalog model ID through every entry point and resolve that exact provider for the run; never silently substitute a different model, simulated response, or template as a completed result. Provider, empty-output, and interrupted-stream failures leave the saved draft intact and remain errors. A failed web lookup may produce a clearly labeled synthesis from the selected model using saved context or explicitly unverified model knowledge. Selected provider/model/search mode/template/project must reach the actual dispatch path. Broken structured output degrades safely to readable content.
- Web failure/zero results is labeled honestly. Local fallback cannot masquerade as web-backed evidence. Import preserves external authorship and source metadata; offline access must match the saved artifact.
- Trackers obey saved cadence/time semantics, pause/resume/run-now, duplicate prevention, and the continuity window. Deleting a tracker preserves generated digests.
- Ollama connections accept a server root, native `/api` base, or compatibility `/v1` base; discovery, JSON generation, streaming and embedding use the same native API URL builder while preserving reverse-proxy prefixes and the selected model. Apply configured provider authentication consistently. A Settings search test checks retrieval only, never model generation. Model-side Research errors must not be labeled as DuckDuckGo/Web Search failures, and failed generation keeps the inquiry draft.
- Provider connectivity, model capability, selected/default model, saved state, and search availability are separate facts. Native runtime must not surface browser demo records or deterministic test responses as genuine results.
- The shell and local saved knowledge work without external assets/services. Secrets remain masked and absent from logs/evidence. Exposed account/storage controls must perform their advertised behavior or state their limitation clearly.
